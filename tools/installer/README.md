# Установщик ONEXTweaks

Установщик состоит из пользовательского этапа регистрации MSIX и двух административных этапов для подготовки и завершения установки. Кандидат 0.29.1110.0 включает виджет, Bridge, PowerAgent и CompanionLauncher. Подпись кандидата предназначена для разработки.

## Единый Setup для GitHub Releases

На Windows 11 x64 с установленным Xbox Game Bar скачайте `ONEXTweaks-Setup-x64.exe`, запустите его и нажмите **Install**. Setup регистрирует MSIX в аккаунте, который запустил установку, и подготавливает компоненты в `Program Files`. Для отдельных установщиков зависимостей Windows может запросить подтверждение. Если Setup сообщает о перезагрузке, после входа снова запустите тот же файл. На ONEXPLAYER 3 должны быть установлены совместимые компоненты OneXConsole.

В бета-сборке при первой установке Setup показывает издателя и SHA-256 сертификата ONEXTweaks. Отпечаток сертификата для этой беты — `3528C48A4FDA614E65867847122ACC776F4AAC1127FF898259D9D9DBCF2D7263`. После подтверждения Setup добавляет сертификат виджета в **Trusted People** на этом компьютере. При обновлении с тем же сертификатом этот диалог пропускается. Если пользователь отклоняет запрос, установка останавливается. Для запуска скачанного из интернета EXE Windows может показать предупреждение SmartScreen.

Доверие к сертификату сохраняется как отдельная настройка Windows. После удаления всех тестовых пакетов ONEXTweaks его можно снять через `certlm.msc` в **Trusted People → Certificates**. Для этого найдите `ONEXTweaks Development` с отпечатком `2CB0B413C8717DBE8AA2303A1C3DFADFB50C9D72` в поле **Thumbprint**.

Для сборки сначала подготовьте комплект через `build_runtime_bundle.py`. В комплект входят подписанный MSIX, манифест среды выполнения и подготовленные фреймворки. Затем сформируйте встроенный архив в новой папке.

```sh
python3 tools/installer/setup/build_payload.py /path/to/bundle /path/to/setup-input
```

На сборочной Windows запустите `Build-ONEXTweaksSetup.ps1` из этой папки. Параметры `-SignTool`, `-CertificateThumbprint` и `-TimestampUrl` указывают на инструмент Windows SDK, сертификат из хранилища сборочного пользователя и доверенную службу отметок времени. `-OutputDirectory` задаёт папку результата. Setup строится штатным компилятором .NET Framework для x64. В публичный релиз входит файл `ONEXTweaks-Setup-x64.exe` с проверенной SHA-256.

Для бета-версии передайте `--beta` при упаковке. Этот режим с помощью `openssl` сверяет закреплённый сертификат из MSIX и включает диалог доверия в Setup. Для локальных прогонов с уже доверенным сертификатом используйте `--development`. В обычной сборке `build_payload.py` требует релизного издателя. Подписанный релизный MSIX с новым идентификатором требует отдельной проверки переноса данных с тестовой сборки.

## Регистрация виджета

Откройте 64-битную Windows PowerShell 5.1 из той учётной записи, где должен появиться виджет. Передайте подписанный MSIX и SHA-256 из доверенного описания релиза. Обычный запуск выводит план. Поместите отдельные APPX/MSIX-фреймворки из сборки в `Dependencies\x64` или `Dependencies\neutral` рядом с MSIX виджета. Скрипт найдёт их сам. Требования берутся из манифеста собранного виджета. Для отдельной лабораторной сборки пути также можно передать через `-FrameworkPackage`.

```powershell
$widget = @{
    WidgetPackage = '.\ONEXTweaks.Widget.msix'
    WidgetSha256 = '<SHA-256 из описания релиза>'
}
$plan = & .\Install-ONEXTweaksWidget.ps1 @widget
$plan | Select-Object Operation, CurrentWidgetVersion, GameBarVersion, Backend, RtssTask, Blockers | Format-List
$plan.Frameworks | Format-Table Name, MinVersion, Source
$plan.Drivers | Format-Table Name, Status
$plan.Applications | Format-Table Name, Status
$plan | Select-Object OneXConsoleStartup
$plan.DependencyLinks | Format-List Name, RequiredFor, Setup, Url
& .\Install-ONEXTweaksWidget.ps1 @widget -Install -WhatIf
```

Для установки на тестовой Windows вызовите скрипт с `-Install` из учётной записи владельца виджета. Windows может показать запрос UAC для отдельных установщиков драйверов. Ввод учётных данных администратора для установки драйвера не меняет владельца регистрации виджета. Если скрипт запущен с повышением прав, перед изменениями он сверяет владельца рабочего стола. Для автоматизированной установки можно явно передать ожидаемый `-TargetUserSid`.

Скрипт скачивает отсутствующие PawnIO, usbip-win2 и HidHide, проверяет SHA-256, цифровую подпись и издателя каждого установщика и запускает их в тихом режиме. Он проверяет наличие файла `.sys`, на который ссылается служба, её состояние и версию драйвера. Если драйверу нужна перезагрузка, выбранный пользователь продолжает установку после следующей загрузки. Подготовка закрепляет этапы за SID пользователя рабочего стола. Запуск от другого пользователя не продолжит эту установку.

У HidHide 1.5.230 файл `HidHide.sys` имеет версию 1.4.181.0. Если драйвер установлен через INF, установщик распознаёт этот файл по SHA-256 и сохраняет существующие привязки устройств.

При отсутствии RTSS установка скачивает архив RivaTuner Statistics Server 7.3.7, проверяет SHA-256 архива, SHA-256 вложенного установщика и подпись MSI, затем запускает установщик в тихом режиме. После установки проверяются `RTSS.exe` и `RTSSHooks64.dll` в каталоге, который использует Bridge. Существующая установка RTSS и её профили сохраняются. [Релиз Guru3D](https://www.guru3d.com/download/rtss-rivatuner-statistics-server-download/) · [Манифест WinGet](https://raw.githubusercontent.com/microsoft/winget-pkgs/master/manifests/g/Guru3D/RTSS/7.3.7/Guru3D.RTSS.installer.yaml)

Пакет и недостающие фреймворки передаются штатному механизму AppX. Windows проверяет подписи и доверие при регистрации. Скрипт повторно считывает версию, архитектуру и состояние зарегистрированного виджета. При повторном запуске здоровая регистрация и подходящие установленные драйверы пропускаются. Обновление использует того же издателя и штатное обновление пакета с сохранением данных. Самоподписанный пакет разработки подходит для лабораторной машины, на которой уже настроено соответствующее доверие. Для будущего распространения нужна релизная подпись.

`WidgetRegistered`, `PrerequisitesReady`, `Backend` и `RtssTask` показывают разные этапы готовности. Для подтверждения Bridge проверяются задача запуска, действующий процесс в нужном пользовательском сеансе и свежий отчёт со совпадающими PID, версией и семейством MSIX. Этот скрипт регистрирует виджет и устанавливает зависимости. Проверка полного комплекта остаётся отдельным этапом и `SetupComplete` остаётся `false`.

Для проверки состава пакета в PowerShell 7 на macOS используйте `-InspectPackage`. Это проверяет контрольную сумму, идентификатор и манифест MSIX. Тест `Test-ONEXTweaksWidgetInstaller.ps1` проверяет те же входы через обычную точку входа. В Windows PowerShell он также прогоняет сценарии развёртывания с подменёнными вызовами AppX.

Документация Windows. [Регистрация пакета и зависимостей](https://learn.microsoft.com/en-us/powershell/module/appx/add-appxpackage?view=windows-11) · [Подпись и распространение MSIX](https://learn.microsoft.com/windows/msix/package/signing-package-overview)

## OneXConsole на ONEXPLAYER 3

- Установщик проверяет совместимые файлы в штатной папке OneXConsole. Если их ещё нет, он может запустить проверенный пакет `Dependencies\OEM\OneXConsole-0.10.4-fix3.exe`. Перед запуском проверяются хеш пакета и подпись Shenzhen One-Netbook. Публичная ссылка на этот точный пакет и разрешение на включение его в общий дистрибутив пока не подтверждены.
- Аппаратный этап проверяет модель ONEXPLAYER 3 и совместимость компонентов OneXConsole. Для установки нужен PowerAgent с чтением TDP и хотя бы одним рабочим каналом управления — PL1/PL2 или вентилятором. PowerAgent определяет доступность вентилятора, лимита зарядки, подсветки и дополнительных кнопок по ответам аппаратных интерфейсов на каждой консоли. На обычной Windows устанавливается виджет с Bridge.
- Если запущенная при входе OneXConsole удерживает аппаратный канал, завершающий этап с `-Complete` сохраняет исходный автозапуск и возвращает `RestartRequired = True`. После обычной перезагрузки Windows установка завершает передачу по трём свежим чтениям из того же сеанса. Для завершения передачи нужны свежие показания TDP и подтверждение, что доступны запись PL1/PL2 или чтение вентилятора с тахометром. Ошибка или разрыв сеанса сбрасывает серию. При сбое проверок установка освобождает захват контроллера и аппаратный канал, восстанавливает автозапуск OneXConsole и запускает её штатную задачу. Если Windows остаётся на прежней загрузке, прерванную передачу можно отменить через `-RestoreOneXConsoleStartup`.
- Завершающий этап сверяет владельца установки, текущее состояние зависимостей, защищённые файлы и задачи, живой Bridge и свежие аппаратные данные. После этого он отключает известную задачу `OneXConsole` с точным VBS и сохраняет её исходное состояние. OEM-сервисы остаются доступны. Пакетный помощник 1110 передаёт обычный запуск установленному Launcher. Интерфейс OneXConsole можно открыть вручную.

## Контракт сборки Bridge и помощников

- Bridge и DependencyManager получают точное семейство подписанного MSIX через `-p:OnexWidgetPackageFamily=<PackageFamilyName>`. Одно значение используется для активации Game Bar, проверки клиента и доступа к LocalState. Сборки разработки используют прежнее семейство пакета по умолчанию.
- Bridge публикуется самодостаточно через `dotnet publish -r win-x64 --self-contained true`. Постоянный путь для установки — `%ProgramFiles%\ONEXTweaks\WidgetBridge\ONEXTweaks.WidgetBridge.exe`. В папке должен быть отдельный `ONEXTweaks.ControllerObserver.exe`, создаваемый при публикации. Launcher собирается с `-p:OnexInstalledDistribution=true`.
- При переносе Bridge прежний владелец должен освободить захват. Журнал действующего или незавершённого захвата хранится в прежней пользовательской папке. Новый Bridge не переводит задачу восстановления на новый путь, пока остаётся журнал или уже запущена старая задача восстановления. Перенос допускается только для задачи текущего пользователя с известной конфигурацией.

## Этапы чистой установки

1. На чистой x64 Windows установите Game Bar из Microsoft Store. Используйте доверенный MSIX. В локальном комплекте 1110 все пять оригинальных Microsoft APPX уже лежат в `Dependencies\x64` рядом с MSIX. Отдельный тест чистой машины должен подтвердить регистрацию до установки драйверов.
2. Из локального рабочего стола выбранного пользователя запустите административный `Initialize-ONEXTweaksReleaseRuntime.ps1 -Prepare -WidgetPackageFullName <точное имя>`. Этот этап записывает исходную регистрацию, SID владельца и новый идентификатор установки. Предварительная проверка доступна через `-WhatIf`.
3. Из обычного процесса владельца запустите `Install-ONEXTweaksWidget.ps1 -Install` с параметрами пакета и его SHA-256. Продолжите от того же пользователя после перезагрузки, если её запросил поставщик драйвера.
4. Административный `Initialize-ONEXTweaksReleaseRuntime.ps1 -RuntimeManifest <путь> -RuntimeManifestSha256 <SHA-256>` проверяет каждый файл и размещает комплект в `Program Files`. Он регистрирует задачи Bridge, автозапуска, восстановления контроллера и RTSS. PowerAgent работает от SYSTEM, проверяет SID и активный сеанс, принимает запросы от установленного Bridge. Владельцу Windows предоставляются чтение и запуск задачи PowerAgent. `build_runtime_bundle.py` создаёт манифест из готовых компонентов.
5. Запустите виджет от владельца рабочего стола. После проверки аппаратного канала и запуска RTSS выполните защищённый `Tools\Installer\Complete-ONEXTweaksRelease.ps1 -Complete`. При выполнении условий он переключает автозапуск OneXConsole. Опция `-RestoreOneXConsoleStartup` возвращает управление OEM по записи установки.

Этот путь рассчитан на первую установку ONEXTweaks, в том числе на ONEXPLAYER со штатной OneXConsole. Для переноса уже развернутого dev-runtime нужны отдельные проверка захвата, резервная копия и проверяемый откат. RTSS 7.3.7 требует повышения прав при запуске. Полноценный оверлей в аккаунте без административного токена требует отдельной приёмки. Новый начальный набор подсветки используется как стартовый выбор первой установки. Физический цвет не определяется из этого файла.

## Обновление 1109 до 1110

Запустите штатный сценарий из повышенного Windows PowerShell 5.1 на рабочем столе того же пользователя, которому принадлежит виджет. Пакет 1109 для возврата можно включить в комплект через `--rollback-widget`.

```powershell
$bundle = Get-Content -LiteralPath .\test-bundle.json -Raw | ConvertFrom-Json
$upgrade = @{
    WidgetPackage = $bundle.WidgetFile
    WidgetSha256 = $bundle.WidgetSha256
    RollbackPackage = $bundle.RollbackFile
    RuntimeManifest = '.\Runtime\runtime-manifest.json'
    RuntimeManifestSha256 = $bundle.RuntimeManifestSha256
}
& .\Setup\Installer\Update-ONEXTweaksRelease.ps1 @upgrade -Upgrade
```

Setup берёт SHA-256 нового MSIX из своего проверенного встроенного комплекта. При отдельном запуске сценария берите SHA-256 из доверенного комплекта конкретной сборки. Прежний вызов без `-WidgetSha256` поддерживает архивный пакет 1110.

Без `-Upgrade` эта же команда проверяет исходную регистрацию и конфигурацию задач. При обновлении установщик проверяет, что может восстановить каждую существующую задачу с прежними правами, освобождает захват контроллера и сохраняет аварийную копию профилей в папке пользователя. Windows обновляет пакет на месте. Установщик подтверждает связь с новым Bridge и запуск RTSS до завершения перехода и переключения автозапуска OneXConsole. При прерывании используйте `Update-ONEXTweaksRelease.ps1 -Recover` из того же аккаунта. Защищённая копия старого аппаратного комплекта сохраняется для восстановления.

Новые журналы установки хранятся в защищённой папке `%ProgramData%\ONEXTweaksInstaller\Installation`. Уже созданный защищённый журнал по прежнему пути доступен для продолжения и удаления. Резервные копии Game Bar в `%ProgramData%\ONEXTweaks` остаются на месте.

## Удаление и откат

1. `Uninstall-ONEXTweaksRelease.ps1 -Report` показывает зарегистрированные файлы, задачи и пакет, которыми владеет установка. `-WhatIf` сохраняет текущие настройки и компоненты.
2. Запустите `-Uninstall` от владельца виджета. Сначала освобождается захват контроллера. Если восстановление не подтверждено, удаление останавливается до снятия пакета. Затем копируются локальные данные виджета и восстанавливаются изменённые ONEXTweaks настройки Guide и стартовой страницы Game Bar. Если пользователь уже изменил эти значения, сохраняется его выбор. `-DiscardWidgetData` отключает резервное копирование данных виджета.
3. Повышенный этап по журналу освобождает аппаратное управление, восстанавливает исходный автозапуск проверенной OEM-задачи и удаляет собственные файлы и задачи. При временном расхождении Windows повторно читает определение задачи. Удаление требует совпадения с защищённой записью установщика. Общие драйверы, RTSS и OneXConsole сохраняются. Журнал позволяет повторить незавершённый этап.
4. После удаления проверьте повторную установку и доступность резервной копии профиля. На ONEXPLAYER подтвердите запуск интерфейса OneXConsole при следующем входе, режим Hardware в Game Bar и Steam, управление вентилятором и зарядкой, отсутствие оставшихся задач ONEXTweaks.

Для проверки восстановления нужны исходно включённый и исходно выключенный автозапуск OEM. После удаления задача должна вернуться в исходное состояние, а вручную изменённые параметры Guide и Game Bar должны сохранить новое значение. Для проверки отказа прервите установку до переключения OneXConsole и повторите административный этап из того же аккаунта.

## Приёмка на устройстве

1. Основной сценарий первой установки начинается с Windows 11 x64 со штатной OneXConsole. Перед запуском установщика ONEXTweaks войдите в систему и подтвердите, что штатный автозапуск уже запустил интерфейс OneXConsole. Проверьте завершение установки при работающей OneXConsole, отключение её автозапуска, первую перезагрузку, удаление и повторный запуск OneXConsole при следующем входе. Повторите удаление с исходно выключенным автозапуском OneXConsole и убедитесь, что сохранён её исходный статус.
2. На физической ONEXPLAYER подтвердите передачу аппаратного канала вентилятора и проверьте Fan Auto и ручную кривую с возвратом в Auto, TDP с возвратом исходных лимитов, LED и зарядку. Сверьте показания после первого входа, перезагрузки и сна. Проверьте открытие виджета кнопкой корпуса, автозапуск без открытия Game Bar, оверлей в игре и ручной запуск OneXConsole.
3. В отдельном сценарии Windows x64 проверьте установку зависимостей с нуля, регистрацию, перезагрузку с продолжением, автозапуск On и Off, открытие вручную и удаление. Повторите из обычного аккаунта с повышением через отдельного администратора. Во время ожидающей перезагрузки второй аккаунт не должен перехватить установку.
4. Выполните переходы Hardware → Virtual Xbox 360 → Hardware и Hardware → DS4 → Hardware в Game Bar и Steam. После возврата в Hardware должен остаться физический контроллер. Сверьте поведение после перезагрузки и сна, затем выполните сценарий удаления.

## Текущая проверка

- На чистой Windows 11 x64 в ВМ проверены регистрация MSIX, установка зависимостей, перезагрузка, запуск виджета и удаление. Отдельный прогон подтвердил штатное обновление с открытой 1109, откат после намеренного сбоя и сохранение тестовых данных.
- На ONEXPLAYER 3 проверены переход с 1109 на 1110, запуск после перезагрузки, PowerAgent, RTSS и сохранение четырёх файлов профилей. При установке автозапуск OneXConsole отключился. После удаления он восстановился, и интерфейс OneXConsole автоматически запустился при следующем входе.
- При повторной чистой установке после удаления проверен первый запуск с аппаратными 12/13 Вт и сохранённым профилем 40/41 Вт. Исправленный Bridge применил 40/41 Вт. Все четыре файла профилей побайтно совпали с резервной копией, аппаратное чтение вентилятора и RTSS прошли проверку.
- На физической ONEXPLAYER проверена установка поверх уже запущенной при входе OneXConsole. После обычной перезагрузки штатная фоновая задача получила подтверждение Fan и TDP, завершилась с кодом 0 и сохранила автозапуск OneXConsole выключенным. После этого виджет и RTSS прошли проверку.
- В следующем варианте установщика фоновый переход также завершился с кодом 0. При первой проверке из виджета чтение Fan прервалось по тайм-ауту. После целевого перезапуска PowerAgent и следующей обычной перезагрузки пять свежих замеров из виджета подтвердили Fan и TDP 40/41 Вт. RTSS работал, четыре файла профилей совпали с резервной копией. Причина разового тайм-аута Fan пока не подтверждена.
- Установщик сохраняет стадии чтения Fan и подключения к аппаратному помощнику в каталоге `PowerAgent`. При достижении 128 КиБ журнал `hardware-health.jsonl` заменяется новым, хранится одна предыдущая копия. Удаление очищает оба файла. В одном из физических прогонов первый запуск виджета через 195 секунд подтвердил Fan, тахометр и 40/41 Вт без перезапуска PowerAgent.
- Повторный прогон на ONEXPLAYER воспроизвёл устаревание отчёта Bridge до 15–16 секунд при занятом канале OneXConsole. Установщик допускает такой отчёт от проверенного процесса для подготовки перезагрузки с восстановлением OEM при сбое. Для завершения требуется новая серия исправных замеров. Кандидат прошёл этот этап и после перезагрузки подтвердил Fan, 40/41 Вт, RTSS и сохранность четырёх профилей.
- На Windows 11 x64 в ВМ подлинная подписанная OneXConsole установилась до виджета. Установка, открытие виджета и удаление текущего пакета 1110 завершились, OneXConsole и контрольный профиль сохранились. На обычном виртуальном оборудовании OneXConsole не создала OEM-задачу. Переключение её автозапуска проверено на физическом ONEXPLAYER.
- Отдельной приёмки требуют установка обычным пользователем с повышением через другой аккаунт, релизная подпись и игровые сценарии на устройстве.
